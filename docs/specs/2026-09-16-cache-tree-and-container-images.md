# 缓存对象目录树、容器镜像视图与搜索

> Status: Approved
> Owner: katch
> Last updated: 2026-09-16

**Objective:** 让运维者在管理界面里按「上游主机 → 路径逐段」的目录树浏览、搜索和清理缓存对象，
并在一个独立的「容器镜像」页里按仓库查看、搜索和删除 registry 上游缓存下来的镜像与 tag。

**Hard invariant:** 被 pin 的对象不被任何批量清除带走（按目录、按镜像都一样），跳过的条数必须报出来；
清除只删引用计数归零的内容文件，不把另一条仍在引用同一摘要的记录变成坏缓存；
拉取路径、缓存键格式与库表结构不变，不新增迁移。

## Problem

1. **平铺表答不出「某个目录下缓存了什么、占多少」。** 当前缓存对象页是一张按最近访问倒序、
   每页 20 条的平铺表（`frontend/src/routes/admin/cache-screen.tsx`，页码固定为 1，
   `internal/service/cache_svc/cache.go:816` 的 `Search`）。缓存键是上游侧路径
   （`cache.go:305` 的 `cacheKey`），天然是层级结构，但界面上看不到任何一层的对象数与体积；
   几十万条的规模下，想知道 `docker.io/library/redis` 占了多少只能靠关键字搜出来再心算，
   而且每页只有 20 条，心算都算不全。
2. **只能逐条清除或整上游清除，没有中间粒度。** `PurgeCacheRequest`
   （`internal/api/admin/cache.go`）只接受单个 ID 或整个上游；界面上的批量清除是前端逐条发请求。
   清掉一个镜像或一个 APT 发行版目录，要么点几百次，要么把整个上游清空。
3. **容器镜像没有自己的视图。** Git 镜像有独立页面（`frontend/src/routes/admin/git-mirrors-screen.tsx`），
   而 registry 缓存只能在平铺表里看到 `/<仓库>/manifests/<引用>` 和 `/<仓库>/blobs/sha256:…` 这样的散条目，
   看不出「缓存了哪些镜像、各有哪些 tag、tag 是否已过期」。
4. **同一个镜像在库里可能分成两种键。** registry 的 `library/` 补全发生在回源时
   （`internal/proxy/registry/registry.go` 的 `upstreamPath`），缓存键取的是补全**之前**的路径
   （`internal/service/proxy_svc/proxy.go:46`），因此 `docker.io/redis` 与 `docker.io/library/redis`
   两种拉法会落成 `/redis/...` 与 `/library/redis/...` 两组键。按键原样归并的镜像视图会把同一个镜像显示成两个。
5. **同一个 tag 可能有多条记录。** manifest 请求按 Accept 分变体存储（`internal/service/cache_svc/variant.go`），
   键末尾缀有 `0x1F` 分隔的变体段；把键原样当成名字显示，界面上会出现不可见字符和重复的 tag。

## Actors and user stories

1. 作为**运维者**，我希望像文件管理器一样逐层展开缓存目录并看到每层的对象数与体积，这样我能找到占空间的地方。
2. 作为**运维者**，我希望能直接清掉一个目录，这样清理一个镜像或一个发行版不必逐条点。
3. 作为**运维者**，我希望在当前目录下搜索路径片段并看到匹配项落在树的哪个位置，这样我能在几十万条里定位对象。
4. 作为**运维者**，我希望有一个容器镜像页列出缓存过的镜像、tag 和它们的状态，并能按镜像或按 tag 删除，
   这样我不必理解 registry 的键格式就能管理镜像缓存。

## Design decisions

| # | 决策 | 依据与被否方案 |
|---|---|---|
| 1 | 目录层级与镜像归并**在服务端按需聚合**，一次只返回一层（或一页镜像），不新增表、列或迁移 | 已验证：键是上游侧路径、`(upstream_id, key)` 有唯一索引（`migrations/cache_object.go:39`），按前缀取一层可直接在现有表上求出。否决：前端拿平铺分页结果自己拼树——每层的对象数和体积在只拿到一页时是错的。否决：落一张目录物化表——拉取路径每次写入都要同步维护，且与首版「缓存记录是唯一真相」相悖 |
| 2 | 树交互为**可展开、也可进入**：目录行的三角就地展开，点目录名进入该目录；当前目录反映在页面 URL 上 | 用户决定（设计稿「后台 · 缓存对象 · 目录树」）。URL 承载当前目录，刷新和分享链接能回到同一层。否决：树与平铺表切换——用户选定展开式树 |
| 3 | 树的第一层是有缓存对象的上游主机；之后按键中查询串之前的路径部分以 `/` 分段；查询串与变体段留在叶子上 | 查询串里可以有 `/`，按它分段会凭空长出不存在的目录。叶子显示名去掉变体段，变体以标记显示，满足 Problem 5 |
| 4 | 每一层**最多返回 200 个子项**，目录在前、对象在后，各自按名称排序；超出时显示「加载更多」 | APT 的 `pool/main/` 这类目录可以有上万个子项，一次全给会重演平铺表的问题。否决：沿用最近访问倒序——目录是按名字找的 |
| 5 | 搜索**限定在当前目录下**，对当前目录以下的路径部分做不区分大小写的子串匹配，最多返回 200 个匹配对象；结果以树的形态显示，匹配项的上级目录自动展开 | 用户确认设计稿「目录树 · 搜索」。在根目录搜索即全站搜索；限定范围让深层搜索保持便宜。否决：搜索时切回平铺表——用户选定展开式树 |
| 6 | 按目录清除**跳过被 pin 的对象并报出跳过条数**，执行前要求一次确认，确认处写明将影响的对象数 | pin 的语义同现有按上游清除（`cache.go:836` 起）；二次确认沿用上游页「清除该上游缓存」的现有交互（`upstream-screen.tsx` 的 `confirming`）。按单个对象清除保持现状：不看 pin、无需确认 |
| 7 | 新增「容器镜像」页与左栏导航项，数据来自协议集合含 `registry` 的上游下的缓存对象 | 用户决定（设计稿「后台 · 容器镜像」）。否决：只读列表——用户选了带删除；否决：解析 manifest 显示平台与层数——要读盘解析内容，工作量与风险明显更大 |
| 8 | 仓库名按 registry 协议的**最后一个动词段**（`manifests` / `blobs` / `tags` / `referrers`）切出；上游开启 `library_completion` 时，不含 `/` 的仓库名归并到 `library/<名>` | 切分规则与回源一致（`registry.go` 的 `splitRepository`，仓库名本身可以叫 `blobs`）；归并规则与回源一致，解决 Problem 4。未开启补全的上游不归并 |
| 9 | 同一 tag 的多个 Accept 变体合并为一个 tag 行，行上的摘要取最近访问的那一份，变体数大于 1 时显示变体数 | Problem 5；对运维者来说 tag 是一个东西 |
| 10 | 镜像体积 = 该仓库（含第 8 条归并进来的键）下所有缓存对象的体积之和；共用层在各自镜像里各算一次，页面上写明这一口径 | 用户确认。否决：按摘要去重分摊——同一层归谁没有唯一答案，而且去重后各镜像之和不再等于删除某个镜像能释放的量 |
| 11 | 删除镜像 = 清除该仓库下全部缓存对象；删除 tag = 清除该 tag 的全部变体记录；两者都跳过 pin 并报数，并各要求一次确认 | 与决策 6 同一套语义。删除 tag 不连带清除层：层可能被同仓库的其他 tag 共用 |
| 12 | 现有管理接口（对象搜索、按 ID / 按上游清除、pin）保留不变；目录列表、目录搜索、按目录清除、镜像列表、镜像删除作为新增能力提供 | 上游页的清除按钮仍依赖按上游清除；不改旧契约就没有兼容问题 |

## 缓存对象页

### 目录浏览

前提：已登录管理界面。

- 打开缓存对象页时，顶部容量条与图例保持现状；其下是路径导航和目录树。未指定目录时位于根，
  列出所有有缓存对象的上游主机。
- 路径导航显示 `全部上游 / <主机> / <段> / …`，除当前段外每一段都能点，点击进入那一层。
  导航右侧显示当前目录下的对象总数与总体积，以及「清除本目录」按钮（根目录不显示该按钮）。
- 表格列：名称、对象数、大小、命中、最后访问、操作。
  - **目录行**：展开三角、目录图标、`<名>/`、进入箭头；对象数与大小是该目录下（递归）全部对象的合计；
    命中显示「—」；最后访问是其中最近的一次；操作为「清除」（走决策 6）。
  - **对象行**：文件图标、叶子名（去掉变体段）、短摘要、pin 标记；变体对象另显示变体标记；
    对象数显示「—」；大小、命中、最后访问取自该记录；操作为「清除」（沿用单条清除）。
  - 叶子名为 `sha256:…` 这类很长的名字时截断显示，悬停可看完整键。
- 点击目录行的三角就地加载并展开下一层，再点收起；可以同时展开多个目录，缩进表示层级。
- 点击目录名或进入箭头，当前目录变为该目录，URL 随之变化；浏览器后退回到上一层。
- 一层子项超过 200 个时，该层末尾显示「加载更多」，点击后追加下一批。
- 目录为空（例如刚被清空）时显示空状态文案；URL 指向一个已不存在的目录时同样显示空状态，路径导航仍可点回上层。
- 对象行保留勾选；选中后工具条出现「已选 N 项 · 清除 · 固定/放开」，行为同现状。目录行不可勾选。

### 搜索

- 搜索框的提示文案说明是在当前目录下搜索路径。输入后按现有节流（250ms）发起查询。
- 有搜索词时：树只显示匹配对象及其上级目录，上级目录全部展开；目录行显示其下匹配到的对象数与体积，
  并标注「匹配 N」；匹配到的名称片段高亮；名称本身匹配的目录也作为结果显示（可继续展开看全部内容）。
- 搜索框右侧显示匹配对象总数；超过 200 个时只显示前 200 个，并在表格下方提示输入更具体的路径或先进入目录。
- 无匹配时显示空状态。清空搜索词回到普通浏览，保留当前目录。

### 按目录清除

- 点击目录行的「清除」或「清除本目录」时，出现确认，写明目录路径与将清除的对象数（不含 pin）。
- 确认后清除该目录下全部未 pin 对象，完成后提示「清除 N 个，跳过 M 个已固定」，并刷新当前视图与容量条。
- 清除过程中失败时显示现有的管理操作错误提示；已清除的部分不回滚，刷新后的数字反映实际状态。

## 容器镜像页

前提：已登录管理界面。

- 左栏导航在「Git 镜像」之后新增「容器镜像」。
- 页头：标题「容器镜像」、镜像数量与一句口径说明。工具条：搜索框（按仓库名或 tag 子串匹配，不区分大小写）、
  上游筛选（仅列出协议含 registry 的上游，默认全部）。
- 每行一个镜像：展开三角、`<主机>/<仓库名>`、Tag 数、体积（决策 10）、命中（合计）、最后访问（最近一次）、「删除」。
  默认按最后访问倒序；每页 50 个，超出时显示「加载更多」。
- 展开一个镜像列出其 tag 行，按最后访问倒序：
  - 按 tag 拉取的：tag 名、短摘要、命中、最后访问、「删除」；被 pin 显示「已固定」；
    可变 manifest 已过过期时刻时显示「已过期，下次拉取回源」；变体数大于 1 时显示变体数。
  - 按摘要拉取的 manifest 同样成行，以摘要作名称、换用摘要图标。
  - tag 行的 Tag 数与体积显示「—」。
- 只有层（blob）而没有任何 manifest 缓存的仓库也作为镜像列出，Tag 数为 0。
- 搜索词匹配到 tag 时，该镜像自动展开并只显示匹配的 tag；匹配到仓库名时显示该镜像的全部 tag。
- 删除镜像 / 删除 tag 走决策 11：确认写明对象数，完成后提示清除与跳过条数并刷新列表。
- 没有 registry 上游或没有镜像缓存时显示空状态。
- 表格下方常驻一行口径说明：体积按该仓库下已缓存对象合计，共用层会在各自镜像里各算一次。

## 通用

- 所有新增文案走 `t()`，中英文资源同时补齐；主机名、路径、摘要作为机器字面量不翻译。
- 深色主题沿用现有设计变量，不单独设计。
- 所有新增管理接口与现有接口同一套鉴权；未登录返回与现有接口一致的未授权，前端回到登录页。
- 目录与仓库参数中出现 `..`、空段或超长输入时按参数错误拒绝，不做任何清除。

## Out of scope

- 解析 manifest 内容显示平台、层数或去重后的镜像真实体积。
- 对镜像或目录做 pin（pin 仍只在单个对象上）。
- Git 镜像页的改动与搜索。
- 深色主题的单独设计稿。
- 按大小、访问时间筛选缓存对象（原平铺表设计稿中的这两个筛选本次移除，未实现过）。
